# Alert RCA Automation

Automatically investigate Datadog alerts and publish Root Cause Analysis (RCA) to Google Chat.

Solo project — no team assignment, just fetch → analyse → publish.

## Folder Structure

```
alert-rca-automation/
  CLAUDE.md                          ← Claude Code reads this for context
  README.md                          ← this file
  config.env.example                 ← copy to config.env and fill in secrets
  _mappings.md                       ← Datadog query & monitor filters
  _processed_alerts.md               ← auto-maintained: alert tracking
  _summary.md                        ← auto-generated by /summarise
  .claude/
    commands/
      fetch-alerts.md                ← slash command: poll Datadog for new alerts
      analyse-alert.md               ← slash command: full RCA investigation
      publish-rca.md                 ← slash command: post RCA to Chat
      summarise.md                   ← slash command: dashboard report
  alerts/
    _template.md                     ← reference template
    DD-XXXXX.md                      ← auto-generated per alert
  scripts/
    webhook_server.py                ← receives Datadog / Google Chat webhooks
    publish_rca.py                   ← posts RCA to Google Chat
    fetch_datadog_alerts.py          ← polls Datadog for alerting monitors
    run_pipeline.sh                  ← cron-friendly: fetch → analyse → publish
  requirements.txt
```

## Setup

### 1. Install Python dependencies

```bash
cd alert-rca-automation
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Configure secrets

```bash
cp config.env.example config.env
```

Edit `config.env`:

| Variable | Description |
|----------|-------------|
| `DD_ACCESS_TOKEN` | Datadog Personal Access Token (`ddpat_...`) — **only this, no API/App keys** |
| `DD_SITE` | Datadog site (e.g. `datadoghq.com`) |
| `GOOGLE_CHAT_WEBHOOK_URL` | Incoming webhook URL for RCA replies |
| `WEBHOOK_PORT` | Port for webhook server (default: 8080) |
| `WEBHOOK_SECRET` | Optional shared secret for webhook auth |
| `DD_MONITOR_QUERY` | Datadog monitor search query (default: `status:alert OR status:warn`) |

### 3. Configure monitor filters (optional)

Edit `_mappings.md` to narrow which alerts to fetch (only if using `/fetch-alerts` with `DD_ACCESS_TOKEN`).

### 4. Datadog auth — two options

**Option A — No Datadog API at all (simplest)**
1. Alerts arrive in Google Chat from Datadog
2. Copy alert → `/create-alert-from-chat` or `python scripts/create_alert_from_chat.py --text "..."`
3. Run `/analyse-alert` in Cursor (Datadog MCP handles logs/traces — uses your Datadog login/token)
4. Run `/publish-rca` → posts back to Google Chat

**Option B — Personal Access Token (for auto-fetch)**
1. Datadog → Personal Settings → Access Tokens → Create Token
2. Scopes needed: `monitors_read`, `timeseries_query`, `logs_read`
3. Set `DD_ACCESS_TOKEN=ddpat_...` in `config.env` (no API key or App key needed)
4. Test: `python scripts/test_datadog_auth.py`
5. Fetch: `python scripts/fetch_datadog_alerts.py` or `/fetch-alerts`

### 5. Enable Datadog MCP in Cursor

Ensure Datadog MCP is connected for RCA investigation via slash commands.

### 6. Google Chat webhook (for RCA replies)

1. Open Google Chat space → Manage webhooks → Add webhook
2. Copy the webhook URL into `config.env` as `GOOGLE_CHAT_WEBHOOK_URL`

## Usage

### Manual workflow — no Datadog API keys (Google Chat only)

```bash
# 1. Copy alert from Google Chat and create alert file
/create-alert-from-chat
# or: python scripts/create_alert_from_chat.py --text "Monitor: [Prod] error rate..."

# 2. Investigate using Datadog MCP in Cursor (no API key needed)
/analyse-alert DD-167097893

# 3. Publish RCA to Google Chat
/publish-rca DD-167097893
```

### Manual workflow — with Personal Access Token

```bash
# 1. Fetch alerting monitors (optional — needs DD_ACCESS_TOKEN)
/fetch-alerts

# 2. Investigate a specific alert
/analyse-alert DD-167097893

# 3. Publish RCA to Google Chat
/publish-rca DD-167097893

# 4. Summary report
/summarise
/summarise last 7 days
/summarise service inward-edge
```

### Automated workflow (webhook)

Point Datadog notification webhook to your server:

```
POST http://your-server:8080/webhook/datadog
Header: X-Webhook-Secret: <your-secret>
```

Start the webhook server:

```bash
source .venv/bin/activate
python scripts/webhook_server.py
```

The server will:
1. Parse the incoming alert
2. Create `alerts/{ID}.md` stub
3. Add row to `_processed_alerts.md`
4. Print instructions to run `/analyse-alert`

### Cron polling (alternative to webhook)

```bash
# Every 5 minutes — fetch new alerts
*/5 * * * * cd /path/to/alert-rca-automation && .venv/bin/python scripts/fetch_datadog_alerts.py
```

### Publish RCA via script

```bash
python scripts/publish_rca.py DD-167097893
```

## Datadog Webhook Setup

In Datadog → Integrations → Webhooks:
- URL: `https://your-server/webhook/datadog`
- Custom headers: `X-Webhook-Secret: your-secret`
- Payload: default Datadog alert payload

Or use Datadog Workflow Automation to POST to the webhook on monitor alert.

## Full automation (no copy/paste)

See **[AUTOMATION_SETUP.md](AUTOMATION_SETUP.md)** for complete setup.

Quick start:
```bash
# 1. Add to config.env:
#    ANTHROPIC_API_KEY=sk-ant-...

# 2. Start server
./scripts/start_automation.sh

# 3. Expose with ngrok (if local)
ngrok http 8080

# 4. Connect Google Chat App → HTTP endpoint:
#    https://YOUR-NGROK-URL/webhook/google-chat?secret=YOUR_WEBHOOK_SECRET
```

When Datadog posts alert to Google Chat → auto RCA → RCA posted back.

- Auto-trigger Cursor agent from webhook (Cursor SDK)
- Thread replies in Google Chat (Chat API with service account)
- Link alerts to Jira tickets
- `/find-similar DD-XXXXX` — search past RCAs for same monitor/service
