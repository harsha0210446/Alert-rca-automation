**When**

**Root cause (likely)**
A short-lived failure/latency spike calling the Optimus item-cache dependency (`getNdpsItemCacheUcodes`) tripped the Hystrix circuit breaker. Because no fallback is implemented for this command, every failure surfaced directly as a 5xx to the caller instead of degrading gracefully, which is why even a brief upstream blip crossed this monitor's low threshold (>1 error/5min).

**Confidence**: Medium — the failing dependency and missing-fallback pattern is clearly evidenced; the underlying reason Optimus itself was briefly unavailable is not confirmed (logs access unavailable to dig further).


## Suggested Fix
- Add a Hystrix fallback for `OptimusProxy#getNdpsItemCacheUcodes` (e.g. return cached/stale UCodes or an empty result) so upstream blips don't surface as 5xx.
- Given the monitor threshold is only >1 error/5min, consider whether that's appropriately sensitive for production paging, or whether it should be tuned.
