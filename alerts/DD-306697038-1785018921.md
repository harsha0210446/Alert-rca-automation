## Root Cause Analysis
**What fired**
A 5xx response was recorded on the distributor invoice sync endpoint within a 10-minute window.

**When**
Triggered 2026-07-26 04:05 IST, recovered 2026-07-26 04:16 IST.

**Root cause (likely)**
When rio-commerce-gateway processes a distributor-retailer invoice sync, it tries to publish the resulting event to a Kafka topic via the rio-gate producer service (RioGateProxy#produceKafkaMessage). That call is failing with a bare HTTP 500 (no response body), so the invoice sync fails end-to-end. The failure is on rio-gate's side, not commerce-gateway's own logic — commerce-gateway is just the caller surfacing the downstream failure.

**Confidence**: High — the exact code path is traced from the controller through to the failing Feign call, and it matches the alert's own documented "check logs" search string exactly.


## Suggested Fix
- Investigate rio-gate / rio-gate-producer directly for the actual cause of the 500 (its own logs/traces would show the real exception — commerce-gateway only sees an empty 500 body).
- Add retry-with-backoff or a dead-letter fallback in RioGateProducer.pushToQueue (RioGateProducer.kt:12) so a transient rio-gate blip doesn't hard-fail the invoice sync outright.
- Fix the resource_name tag mismatch on this monitor so future log/trace correlation links work correctly (configured tag doesn't match the live span's actual resource name).
